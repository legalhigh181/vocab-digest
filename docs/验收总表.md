### 第 3 格必须说清的地方

日语人声素材是 Wikimedia Commons 的 **Public Domain** 发音练习（作者 marsian，2006，母语者：
`practice5.ogg` 30.9s モーラ鼻音 14 词、`practice6.ogg` 68.4s 近音词 13 组）。

- 链路：真 whisper → SRT → 日文 digest → 读音/假名/entryKey → Word，全部通过。
- 质量：practice5 的 14 词对约 8–9 个；`玄米` 被切成「ゲン」「マイ」；还出现一句
  「専用本日の動画をご覧いただきありがとうございます。」（典型幻觉）。
  practice6 的长音、促音、撥音「ん」区分基本丢失。
- **结论：日语 ASR 链路可用，`ggml-small.bin` 的日语识别质量不足以宣称已验证。**
  要改善只能换更大模型或调解码参数，本轮不做。

### 3.1 2026-11-11 追加修复：语言没传进转写层（真实 bug）

用户拿 `BV1KE4p6CERE`（「脑洞学生会 也有洞」第 6 话，日语人声 + 画面硬字幕）实测，
结果是**0 个词条**，看着像「没识别到」。查下来是两条链路都漏传语言：

- 前端 `app/public/app.js` 的 `doFetch()` 调 `/api/run/fetch/start` 时只发 `link/withDanmaku/asr`，
  **没发 `language`**；
- 插件 `src/index.js` 的 `vocab_collect` 调 `fetchVideo` 时也没传 `language`。

服务端 `runFetchJob` 收到的是 `undefined`，`src/fetch.js` 于是按 `opts.language ?? 'en'` 调 whisper
——**用英语转写日语人声**，whisper 会输出英文描述与翻译腔（该样本的 `audio.p1.srt` 2097 行里
0 个假名、699 行拉丁字母，全是 `[MUSIC PLAYING]`、`(singing in foreign language)`、`♪ … ♪`）。
英文文本再交给日文分词，自然一个词都抓不到 → digest `language:ja` 但 `items: []`。

修复：两处都把语言显式传下去（`language: digestLanguage()` / `args.language ?? cfg.language`），
并加测试 `T6 · 取数请求里的 language 必须传到转写层`（断言注入的 `fetchVideo` 依次收到 `'ja'` 和 `undefined`）。

反向核对：同一段音频用 `--language ja` 重跑，whisper 输出的是**日文**（31 条，歌词部分能看出日语），
说明「语言传对就有输出」，此前的 0 词条是漏传语言导致的，不是模型完全不能识别。
证据：`docs/evidence-t6-real-whisper-ja-anime.txt`。

修复后把用户那条视频（`BV1KE4p6CERE`，1900s / 31.7 分钟）重跑了一遍：

| 项 | 结果 |
|---|---|
| 转写 | 523s，751 条 SRT，假名字符 3759、拉丁字母 20（之前是 0 假名 / 699 拉丁） |
| 日文 digest | `runs/ja-bv1ke4-demo`：772 个词条、`unknownItemCount: 70`（9.1%）、释义命中 8 |
| 词条样例 | 音楽×109（whisper 把大量 BGM 标成「(音楽)」）、ん×36、する×22、私×16、いや×13、ー×17（未收录） |

**注意**：`音楽` 这种靠 BGM 标记堆出来的高频词说明「转写成功」≠「内容干净」；
`ー`（长音符号）被当成独立词且未收录，是分词层的小噪音，本轮没改。
