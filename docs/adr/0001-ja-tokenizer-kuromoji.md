# ADR-0001：日文形态分析选用 kuromoji 0.1.2（IPADIC）

日期：2026-11-10
状态：已采纳（经 T0 探针实测）

## 背景

vocab-digest 原本只支持英语：`tokenize.js` 只匹配拉丁字母，`clean.js` 对不含
ASCII 字母的片段直接丢弃（reason: `no-latin`），词形还原依赖 `lexicon/lemmatize.js`
的英文规则。要支持日文，必须引入真正的日语形态分析，因为：

- 日语没有空格分词，正则切不出来；
- 日文动词/形容词有活用（食べました → 食べる、美しかった → 美しい），
  `Intl.Segmenter` 只切分不还原；
- 需要读音（振り仮名）和词性，正则拿不到。

## 候选与决策

| 候选 | 结论 |
|---|---|
| `Intl.Segmenter` | ✗ 只做切分，无原形、无读音、无词性。不能作为完成标准。 |
| 汉字/假名正则切分 | ✗ 就是方案禁止的「用一个汉字 regex 冒充日语分词」。 |
| 自建词典 + 规则 | ✗ 词典数据与维护成本远高于依赖现成分词器。 |
| **kuromoji 0.1.2（IPADIC）** | ✓ 采纳 |
| Python 侧（janome/fugashi） | ✗ 引入第二个运行时，与现有纯 Node 部署冲突。 |

分词实测（IPADIC，未经任何后处理）：

```

  昨日|昨日|キノウ|名詞|副詞可能
  食べ|食べる|タベ|動詞|自立        ← basic_form 正确
  食べる|食べる|タベル|動詞|自立    ← 两次都归到食べる

ｺｰﾋｰ   → *|*|_|名詞|一般                             ← 半角片假名未命中
```

## 由探针发现、必须在实现中处理的三个事实

1. **活用词的 `reading` 是活用后的读音，不是原形的读音。**
   `食べました` 的 token reading 是 `タベ`，而原形「食べる」的读音是 `タベル`。
   → 词条读音**不能**直接取 token 的 reading 当原形读音。做法：先 NFKC 规范化后
   单独对 `basic_form` 分词一次取读音并缓存；取不到则留空并标记，不拼造。
2. **`basic_form === '*'` 表示词典未命中（未知词）。**
   → 回退用 `surface_form` 作 lemma，标记 `unknown: true`、`lemmaSource: 'surface'`、
   读音留空。**不得宣称已完成词形还原。**
3. **半角片假名（`ｺｰﾋｰ`）直接喂给分词器会落到未知词。**
   → 分析文本必须 NFKC 规范化后再分词；但**原字幕原文保留不动**，
   并建立「分析文本 → 原文」的 UTF-16 offset 映射，保证例句能精确定位。

## 已知限制（不得对外宣称已解决）

- 未知词比例**未经验证**。不写「约 5-10%」这类估计值为结论；验收时分别统计
  「未知词出现次数占比」与「去重词条占比」，并人工抽查。
- 词典命中 ≠ 分词正确或读音正确（同形异读、专名、复合词都会出错）。
- **分词词典不是日汉词典**。kuromoji 不提供任何中文释义。
- 首版 ja 不启用短语抽取（英文 PMI/空格 n-gram 不适用于日语）。

## 迁移与回退

- 旧英文流程完全不变；`digest()` 同步契约保留。
- 新增异步 `runDigestAsync` / `prepareLanguageRuntime`，只在 ja 路径需要。
- 若后续发现 kuromoji 无法满足需求，替换点集中在 `src/languages/ja*.js`，
  不影响英文链路与既有数据。
